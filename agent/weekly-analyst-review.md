# 每週分析師重點排程：工作說明

這份說明給 Claude 的「每週分析師重點」排程使用。每週六上午執行一次，檢查 `data/companies.json` 裡每家公司的分析師關注重點、預估 EPS、前景產品與比較同業是否需要更新。

## 1. 準備

這份說明在 GitHub Actions 裡執行，repo 已經 checkout 在工作目錄，不需要 clone，也不要自己執行 git 指令。提交與推送由 workflow 在你結束後處理，而且只會提交 `data/companies.json`，改其他檔案不會生效。

## 2. 逐家公司檢查

對每家公司依序查證以下五項，每項都要有本週可查到、有日期的來源。

### a. 預估 EPS（`eps`）

- 搜尋最新的「Factset 最新調查：<公司名>」（鉅亨網或豐雲學堂轉載），打開文章讀數字：
  - 今年與明年 EPS 的中位數、最高、最低。
  - 分析師人數。
  - 目標價。
  - 發布日期。
- 只有找到比現有 `eps.date` 更新的調查時才更新，數字必須和文章一致。
- 找不到新調查就保持不變。不可自行估算或混用不同來源的數字。

### b. 成長主軸（`thesis`）

- 搜尋最近的法說會、外資報告摘要、主要媒體的產業分析，確認分析師目前最關注的成長驅動力。
- 主軸沒變就不要改寫；有變化時改寫，用 `**粗體**` 標出主軸，並說明為什麼挑這些比較同業。

### c. 比較同業（`peers`）

- 同業依成長主軸挑選，挑真正競爭同一塊市場的公司。例如聯發科的主軸是 AI ASIC，就比博通、Marvell、創意、世芯，而不是其他手機或消費性 IC 設計公司。
- 主軸改變或出現新的主要競爭者時才調整。
- 每家同業要有正確的 Yahoo Finance 代號：上市 `.TW`、上櫃 `.TWO`、韓股 `.KS`、港股 `.HK`、日股 `.T`、美股直接用代號。
- 和本業有關、但不屬於成長主軸的公司，可以加 `"ref": true` 只當參考。

### d. 前景產品（`outlook`）

保持 3 到 5 條，每條一句，用自己的話寫。過時的內容（已發生的時程、被推翻的預期）要更新或移除。

### e. 來源與日期

- `sources` 換成實際用到的 2 到 4 個來源，格式 `["內容（媒體，YYYY/MM/DD）", "網址"]`。
- `reviewed` 改成今天的日期。

## 3. 記錄本週變化（`changes`）

- 只要上面任何一項有實質變化，就在該公司的 `changes` 陣列最前面加一筆 `{"date": "YYYY-MM-DD", "text": "一句話說明改了什麼、為什麼"}`。例如：「FactSet 2027 EPS 中位數由 141.4 上修至 150.2 元」。
- 保留最近 4 筆。
- 沒有變化就不加，但仍更新 `reviewed`。

## 4. 規則

- 所有內容用自己的話改寫，直接引用最多一處且少於 15 字。
- 只寫來源裡有的事實，不加入自己的買賣建議。
- 年份換年後（例如到了 2027 年），`eps` 的 `y26`/`y27` 欄位語意不變。先不要自行改欄位名稱，在回報中提醒維護者需要調整頁面。
- 不要新增公司或刪除公司，那由維護者決定。

## 5. 檢查

1. 執行 `python3 -m json.tool data/companies.json`，確認格式正確，有錯就修到正確為止。workflow 會再驗證一次，格式錯誤會讓這次更新作廢。
2. 最後用幾行文字回報這次做了什麼，回報會留在 Actions 的執行紀錄裡。
