# 每日新聞排程：工作說明

這份說明給 Claude 的「每日新聞」排程使用。每個交易日收盤後執行一次，整理當天台股大盤變化，以及 `data/companies.json` 裡每家公司的重要新聞，寫入 `data/news.json`。

## 1. 準備

這份說明在 GitHub Actions 裡執行，repo 已經 checkout 在工作目錄，不需要 clone，也不要自己執行 git 指令。提交與推送由 workflow 在你結束後處理，而且只會提交 `data/news.json`，改其他檔案不會生效。

## 2. 今日市場

先確認今天（台北時間）台股是否開盤。休市時把 `market` 寫成：`headline` 說明休市原因，`points` 只放一條國際市場的重要變化，然後直接跳到第 3 步。

開盤日搜尋當天的收盤報導（例如鉅亨網、經濟日報、工商時報、中央社），整理：

- `headline`：一句話說明今天大盤怎麼了。包含加權指數漲跌點數與幅度，以及主因。
- `points`：3 到 5 條，每條一句。涵蓋：
  - 主要驅動因素，例如美股、AI 供應鏈、匯率、政策或國際事件。
  - 外資買賣超。
  - 強勢或弱勢族群。
  - 和追蹤公司直接相關的變化。
- `sources`：實際用到的 2 到 4 個來源，格式 `["媒體：標題（日期）", "網址"]`。

## 3. 個股新聞

對每家追蹤公司，用中文和英文各搜尋最近 24 小時的新聞（週一要涵蓋週末）。只收**實質影響基本面或評價**的消息：

- 財報、月營收。
- 法說會。
- 訂單或客戶的得失。
- 新產品或新製程的進度。
- 分析師的評等、目標價或 EPS 預估調整。
- 管制、關稅、訴訟。
- 主要競爭對手的重大消息。

股價漲跌本身、技術分析、論壇文章、重複轉載都不收。每家公司每天最多 3 則，沒有就不加。

每則新聞的欄位：

```json
{
  "date": "2026-10-23",
  "title": "用自己的話寫的標題，20 字內",
  "summary": "一到兩句，說明發生什麼事，以及和這家公司成長主軸的關係",
  "impact": "positive | negative | neutral",
  "thesis": true,
  "source": "鉅亨網",
  "url": "https://..."
}
```

- `impact` 是相對於該公司 `thesis` 的影響。拿不準就用 `neutral`。
- 消息可能改變成長主軸、比較同業或 EPS 預估時，加上 `"thesis": true`。每週分析師排程會優先處理這些。

## 4. 合併寫入 `data/news.json`

- 保留 `_說明`。
- `updated`：現在的台北時間，ISO 格式。
- `market`：`{date, headline, points, sources}`。
- `companies`：
  - 以代號為鍵，新消息放最前面。
  - 依 `url` 去重，同一事件不同媒體只留一則。
  - 刪掉超過 7 天的舊消息，每家最多保留 6 則。

## 5. 寫作與著作權規則

- 標題與摘要一律用自己的話改寫，不可照抄原文句子。
- 引號直接引用最多一處、少於 15 個字，非必要不引用。
- 每則都要附原始連結。找不到可靠來源的消息不收。
- 只寫報導裡有的事實，不加入自己的投資建議或預測。

## 6. 檢查

1. 執行 `python3 -m json.tool data/news.json`，確認格式正確，有錯就修到正確為止。workflow 會再驗證一次，格式錯誤會讓這次更新作廢。
2. 最後用幾行文字回報這次做了什麼，回報會留在 Actions 的執行紀錄裡。
